## Directory Purposes

**raganything/ - Main Package:**
- Purpose: Core RAG-Anything functionality and implementation
- Contains: Python modules implementing document parsing, processing, multimodal analysis, querying, and batch operations
- Key files: raganything.py (orchestrator), modalprocessors.py (multimodal analysis), parser.py (document parsing)

**examples/ - Usage Examples:**
- Purpose: Demonstrate API usage and test document processing capabilities
- Contains: Test scripts for different document formats (Office, images, text)
- Pattern: Async functions that test one feature at a time with comprehensive output

**docs/ - Documentation:**
- Purpose: User and developer documentation for features and setup
- Contains: Markdown guides for offline setup, batch processing, enhanced markdown, context-aware processing
- Key files: Each feature has detailed documentation with examples

**scripts/ - Utility Scripts:**
- Purpose: Development and deployment helper scripts
- Contains: One-off utilities not part of the core package

**assets/ - Media:**
- Purpose: Logos, diagrams, and other media for documentation
- Contains: PNG/SVG files for README and documentation

**.planning/codebase/ - Analysis Output:**
- Purpose: Generated architecture and structure analysis documents
- Contains: ARCHITECTURE.md, STRUCTURE.md (this file), plus CONVENTIONS.md, TESTING.md (when generated)
- Generated by: gsd:map-codebase command

**.github/ - CI/CD and Templates:**
- Purpose: GitHub automation and contribution templates
- Contains: Workflow files for CI/CD, issue templates, PR templates

**.claude/ - Agent Configuration:**
- Purpose: Claude agent-specific configuration for development
- Contains: Agent instructions and rules for code generation

## Key File Locations

**Entry Points:**

- `raganything/__init__.py`: Public API - exports RAGAnything, RAGAnythingConfig, AudioProcessor
- `raganything/raganything.py`: Main orchestrator - RAGAnything class with all functionality via mixin composition
- `examples/office_document_test.py`: Example of parsing and querying documents

**Configuration:**

- `raganything/config.py`: RAGAnythingConfig dataclass with environment variable support for all configurable features
- `CLAUDE.md`: Development workflow and container architecture instructions
- `.env`: Environment variables (not tracked, user creates)

**Core Logic:**

- `raganything/parser.py`: MineruParser and DoclingParser for document → (content_list, markdown) conversion
- `raganything/processor.py`: ProcessorMixin with document processing pipeline (parse, separate, insert)
- `raganything/modalprocessors.py`: ImageModalProcessor, TableModalProcessor, EquationModalProcessor for multimodal content analysis
- `raganything/query.py`: QueryMixin with text and multimodal query support
- `raganything/batch.py`: BatchMixin with concurrent folder/batch processing

**Testing:**

- `examples/office_document_test.py`: Integration test for Office document parsing
- `examples/image_format_test.py`: Integration test for image parsing
- `examples/text_format_test.py`: Integration test for text parsing
- Note: No pytest/vitest suite - examples serve as manual tests

## Naming Conventions

**Files:**

- `*.py`: All Python implementation files use snake_case (parser.py, modalprocessors.py)
- `*_test.py`: Integration test/example files
- `*.md`: Documentation files in root or docs/ directory
- `.env*`: Environment configuration files (not tracked)
- `test_output/`: Generated directory for parser output

**Directories:**

- `raganything/`: Main package uses lowercase with no separators
- `examples/`: Example and test scripts
- `docs/`: Documentation and guides
- `.planning/codebase/`: Analysis output from GSD tools

**Python Naming (inside modules):**

- Classes: PascalCase (RAGAnything, ImageModalProcessor, MineruParser)
- Functions: snake_case (process_document_complete, separate_content)
- Constants: SCREAMING_SNAKE_CASE (AUDIO_FORMATS, OFFICE_FORMATS)
- Private methods: _leading_underscore (\_ensure_lightrag_initialized)
- Type hints: Standard types or custom dataclasses

**Configuration Parameters:**

- Environment variables: SCREAMING_SNAKE_CASE (WORKING_DIR, PARSE_METHOD, ENABLE_IMAGE_PROCESSING)
- Config class fields: snake_case matching env var names converted to lowercase (working_dir, parse_method)
- Dataclass fields: snake_case with optional default_factory for collections

## Where to Add New Code

**New Feature (e.g., new modal processor for diagrams):**

1. **Implementation**: `raganything/modalprocessors.py`
   - Create new processor class (DiagramModalProcessor) inheriting pattern from existing processors
   - Implement `process_modal_item(item, context_extractor, lightrag)` method
   - Add prompt template to `raganything/prompt.py` for analysis

2. **Configuration**: `raganything/config.py`
   - Add new boolean field: `enable_diagram_processing: bool = ...`
   - Add to logging in RAGAnything.__post_init__()

3. **Integration**: `raganything/raganything.py`
   - Register processor in `_initialize_processors()` if config enabled
   - Add to modal_processors dict with appropriate key

4. **Testing**: `examples/new_format_test.py`
   - Create example script following office_document_test.py pattern
   - Test processor with sample diagram files

**New Parser (e.g., HTMLParser):**

1. **Implementation**: `raganything/parser.py`
   - Create new parser class inheriting from Parser base
   - Implement `check_installation()`, `parse(file_path, **kwargs)` methods
   - Return (content_list, markdown_text) tuple matching format

2. **Configuration**: `raganything/config.py`
   - Add parser choice to PARSER field if it's a selectable option

3. **Integration**: `raganything/raganything.py`
   - Add conditional initialization in `__post_init__()` if new parser is selectable
   - Validate format support in `_ensure_lightrag_initialized()`

4. **Format Support**: `raganything/parser.py`
   - Add file extension to appropriate FORMAT constant (e.g., HTML_FORMATS)
   - Update SUPPORTED_FILE_EXTENSIONS in config.py if new formats

**New Query Mode (e.g., 'hybrid' combining text + tables):**

1. **Implementation**: `raganything/query.py`
   - Add new case to aquery() method for new mode
   - Implement logic routing to appropriate modal processors
   - Generate cache key if needed

2. **Testing**: `examples/query_test.py`
   - Create example showing new query mode usage

**Shared Utilities:**

- Location: `raganything/utils.py`
- Pattern: Standalone functions with no state
- Export from main module if part of public API

**Batch Processing Extensions:**

- Location: `raganything/batch.py`
- Pattern: Add new methods to BatchMixin following async/await pattern
- Use existing `process_document_complete()` internally

## Special Directories

**rag_storage/ (Generated at runtime):**
- Purpose: LightRAG storage for knowledge graphs, vectors, KV pairs
- Generated: First time process_document_complete() or aquery() called
- Committed: No - listed in .gitignore
- Cleanup: Delete to reset RAG storage and start fresh

**test_output/ (Generated by examples):**
- Purpose: Output from parser - markdown files, extracted images, metadata
- Generated: When examples run or process_document_complete() called with output_dir
- Committed: No - created by users
- Content: Markdown (.md), extracted images, JSON metadata

**output/ (Default parser output):**
- Purpose: Default location for parsed document output
- Configurable: Via OUTPUT_DIR env var or parser_output_dir config
- Committed: No - user-generated data

**raganything/__pycache__/ (Generated by Python):**
- Purpose: Compiled Python bytecode cache
- Generated: Automatically by Python at import time
- Committed: No - in .gitignore
- Cleanup: Safe to delete, will regenerate on next import
