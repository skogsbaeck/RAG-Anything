elif ext in [".xls", ".xlsx"]:

**Zero-content guard fix (processor.py, around line 440):**

The current unconditional check:
```python
if len(content_list) == 0:
    raise ValueError("Parsing failed: No content was extracted")
```

Must be updated to skip the check for spreadsheet direct parse paths. Per locked decision: zero content from SpreadsheetParser is valid (workbook genuinely had no data).

Change to:
```python
is_direct_spreadsheet = (
    ext in [".xls", ".xlsx"]
    and self.config.enable_direct_spreadsheet_parsing
)
if len(content_list) == 0 and not is_direct_spreadsheet:
    raise ValueError("Parsing failed: No content was extracted")
```

This preserves the guard for all other file types (PDF, images, Office docs, audio, etc.) while allowing zero-content from direct spreadsheet parsing. When direct parsing is disabled (LibreOffice path), the guard still applies — which is correct since LibreOffice + MinerU returning zero content IS a failure.

**Note on internal fallback behavior:** When direct parsing is enabled, `parse_spreadsheet()` may internally fall back to LibreOffice if SpreadsheetParser throws. In that case, `is_direct_spreadsheet` is still True, so zero-content from the internal LibreOffice fallback also bypasses the guard. This is acceptable: if SpreadsheetParser failed AND LibreOffice returned empty, the workbook is genuinely unparseable. There is nothing useful to extract.
